4-1. 분석 대상 고르기 (SQL 함수)

  조인/집계가 들어가서 supabase-py 기본 기능으로는 못 함. 또 API 조회는 1,000행에서
  에러 없이 잘린다. 그래서 SQL 을 Supabase 함수로 등록하고 파이썬에서 rpc 로 부른다.

  조건
    - cmd_hash 가 있는 세션
    - 로그인 성공한 세션
    - 아직 ai_analysis 에 없는 cmd_hash
    - cmd_hash 마다 가장 먼저 나온 세션 1개만 (대표)
    - 같은 해시가 많은 순서 (많이 반복된 공격부터)
    - max_rows 로 하루 상한

  아래를 SQL Editor 에서 실행하고, 같은 내용을 db/02_ai_targets.sql 로 커밋.
  (문법 검사는 통과한 초안. 실제 데이터로 결과 확인 필요)

    CREATE OR REPLACE FUNCTION public.pick_ai_targets(max_rows integer DEFAULT 1000)
    RETURNS TABLE (cmd_hash text, protocol text, sensor_id text, session_id text,
                   commands text, cluster_size bigint)
    LANGUAGE sql STABLE
    AS $$
        WITH candidates AS (
            SELECT s.cmd_hash, s.protocol, s.sensor_id, s.session_id, s.start_ts
            FROM sessions s
            WHERE s.cmd_hash IS NOT NULL
              AND EXISTS (SELECT 1 FROM auth_attempts a
                          WHERE a.sensor_id = s.sensor_id
                            AND a.session_id = s.session_id
                            AND a.success)
              AND NOT EXISTS (SELECT 1 FROM ai_analysis x WHERE x.cmd_hash = s.cmd_hash)
        ),
        ranked AS (
            SELECT c.*,
                   count(*) OVER (PARTITION BY c.cmd_hash) AS cluster_size,
                   row_number() OVER (PARTITION BY c.cmd_hash ORDER BY c.start_ts) AS rn
            FROM candidates c
        )
        SELECT r.cmd_hash, r.protocol, r.sensor_id, r.session_id,
               (SELECT string_agg(m.input, E'\n' ORDER BY m.ts)
                  FROM commands m
                 WHERE m.sensor_id = r.sensor_id AND m.session_id = r.session_id),
               r.cluster_size
        FROM ranked r
        WHERE r.rn = 1
        ORDER BY r.cluster_size DESC
        LIMIT max_rows;
    $$;

    -- 공개 키로 함수를 못 부르게. secret 키(service_role)는 계속 호출 가능
    REVOKE EXECUTE ON FUNCTION public.pick_ai_targets(integer) FROM public, anon, authenticated;

  파이썬
    rows = sb.rpc("pick_ai_targets", {"max_rows": 1000}).execute().data
    # rows = [{"cmd_hash": ..., "protocol": "ssh", "commands": "uname -a\nwget ...", "cluster_size": 812, ...}, ...]


4-2. 프롬프트 (analyzer/prompts/session_intent.md)

  - 분류 기준 6개를 각각 어떤 명령 패턴일 때 고르는지 설명
  - severity 1~5 기준
  - few-shot 예시 여러 개 (명령 → 기대 결과 JSON)
  - 날짜, 요청마다 달라지는 값은 넣지 말 것 (캐시가 깨짐)

  ★ 캐싱 주의
    Haiku 4.5 는 프롬프트가 4,096 토큰 이상이어야 캐시가 된다. 그보다 짧으면 에러 없이
    그냥 캐시가 안 된다. 예산안은 2,000 토큰짜리 프롬프트 캐싱을 가정했는데 그 길이로는 안 먹힘.
    → few-shot 을 넉넉히 넣어 4,096 토큰을 넘기거나, 캐시 없이 가는 비용으로 다시 계산.
    → 실제로 캐시가 됐는지는 결과의 usage.cache_read_input_tokens 가 0 보다 큰지로 확인.
    → Batch 안에서의 캐시는 최선 노력(보장 아님).


4-3. Batch 제출 (classify.py)

  모델: claude-haiku-4-5  (예산안 기준)

    import anthropic
    from anthropic.types.message_create_params import MessageCreateParamsNonStreaming
    from anthropic.types.messages.batch_create_params import Request

    INTENTS = ["코인채굴", "봇넷가담", "정찰", "자격증명탈취", "랜섬웨어", "기타"]
    SCHEMA = {
        "type": "object",
        "additionalProperties": False,
        "required": ["intent", "severity", "summary", "ttp"],
        "properties": {
            "intent":   {"type": "string", "enum": INTENTS},
            "severity": {"type": "integer", "enum": [1, 2, 3, 4, 5]},
            "summary":  {"type": "string"},
            "ttp":      {"type": "array", "items": {"type": "string"}},
        },
    }

    client = anthropic.Anthropic()          # .env 의 ANTHROPIC_API_KEY 를 읽음
    system = [{"type": "text", "text": PROMPT_TEXT, "cache_control": {"type": "ephemeral"}}]

    requests = [
        Request(
            custom_id=row["cmd_hash"],
            params=MessageCreateParamsNonStreaming(
                model="claude-haiku-4-5",
                max_tokens=1024,
                system=system,
                output_config={"format": {"type": "json_schema", "schema": SCHEMA}},
                messages=[{"role": "user",
                           "content": f"protocol: {row['protocol']}\ncommands:\n{row['commands']}"}],
            ),
        )
        for row in rows
    ]
    batch = client.messages.batches.create(requests=requests)
    # batch.id 를 data/ai_batch_id.txt 에 저장

  포인트
    - output_config 의 json_schema 로 응답 형식을 강제 → intent 가 6개 중 하나로만 나옴
    - custom_id = cmd_hash.  결과는 순서가 섞여서 오기 때문에 이걸로 다시 연결
    - custom_id 규칙: 1~64자, 영문/숫자/_/- 만, batch 안에서 중복 금지
        → ② 와 cmd_hash 형식을 맞출 것. sha256 hex(64자)나 md5 hex(32자)면 그대로 됨
        → 4-1 함수가 해시당 1행만 주므로 중복은 안 생김
    - 한 batch 최대 100,000 요청


4-4. 결과 회수 → 저장

    batch = client.messages.batches.retrieve(batch_id)
    if batch.processing_status != "ended":
        return   # 아직. 내일 다시

    rows = []
    for r in client.messages.batches.results(batch_id):
        if r.result.type != "succeeded":
            continue            # errored / expired 는 저장 안 함 → 다음 날 대상에 다시 포함됨
        msg = r.result.message
        text = next(b.text for b in msg.content if b.type == "text")
        out = json.loads(text)
        rows.append({
            "cmd_hash": r.custom_id,
            "intent": out["intent"],
            "severity": out["severity"],
            "summary": out["summary"],
            "ttp": out["ttp"],
            "model": msg.model,
            "tokens_in": msg.usage.input_tokens,
            "tokens_out": msg.usage.output_tokens,
        })

    sb.table("ai_analysis").upsert(rows, on_conflict="cmd_hash", ignore_duplicates=True).execute()
    # 저장 끝나면 data/ai_batch_id.txt 삭제

  포인트
    - 실패한 건 저장하지 않으면 ai_analysis 에 없으니 다음 날 4-1 에서 자동으로 다시 뽑힘
    - 행이 많으면 500개씩 나눠서 upsert (collector/parse_pipeline.py 의 chunks 참고)
    - 토큰 수가 저장되므로 결산 때 실제 비용을 SQL 로 뽑을 수 있음

6. 서버 없이 지금 테스트하는 방법
---------------------------------------------------------------------

  준비
    - 저장소 루트 .env
        SUPABASE_URL=...
        SUPABASE_SECRET_KEY=...      (① 에게 개인 메시지로 받기)
        ANTHROPIC_API_KEY=...        (팀 API 키. 채팅방에 올리지 말 것)
    - pip install -r requirements.txt

  순서
    1) ② 의 샘플 적재:  python -m collector.parse_pipeline --sensor sample
    2) cmd_hash 는 아직 ② 가 안 만들어서 비어 있음. 테스트용으로 SQL Editor 에서 직접 채우기
         UPDATE sessions SET cmd_hash = md5(session_id) WHERE sensor_id = 'sample';
    3) 4-1 함수 실행 결과 확인
         SELECT * FROM pick_ai_targets(10);
    4) 2~3건만 batch 로 보내서 전체 흐름 확인 (비용 거의 없음)
    5) 끝나면 테스트 결과 삭제
         DELETE FROM ai_analysis;          -- 샘플 기간에만
         UPDATE sessions SET cmd_hash = NULL WHERE sensor_id = 'sample';

  pip 설치가 "Windows Long Path support" 에러로 실패하면
    저장소 경로가 길어서 그렇다. 가상환경을 짧은 경로에 만들면 됨
